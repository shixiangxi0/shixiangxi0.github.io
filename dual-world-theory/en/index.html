Dual-World Theory: Another Perspective on Game Architecture

Further reading: How to Understand Dual-World Theory

The Problem of Game Development

Anyone who has worked on games knows this dilemma: you just wanted to tweak the speed of an attack animation, only to find that the timing of damage calculation changed with it; you modified a Buff's value, only to discover that some special effect's trigger logic was buried in a crevice of that code. Logic and presentation are tangled like two balls of yarn—pull one thread and the whole body moves.

The root of the problem isn't that the code isn't well written. It's that we have always understood games through a "what you see is what you get" lens. A character moves on screen, so we think the game world is moving; a health bar decreases, so we think the facts are decreasing. But this perspective conflates "the world itself" with "the projection of the world."

Dual-World Theory proposes a different starting point: a game is first and foremost a deterministic state machine. Player inputs, rule triggers, numerical changes, phase transitions—these are essentially discrete state migrations. The animations, effects, and particles on screen are merely sensory projections of these discrete changes.

Events are the facts; state is merely a projection.

Two Worlds

From this perspective, the system naturally divides into two layers.

Logic Layer: The Facts of the World

The logic layer is the "truth" of the game world. It is responsible for articulating objective world rules, maintaining the complete state of the current scene, and processing all events that change state. It has two core characteristics:

  • Serial: All events are queued and processed one by one. Everything that happens "simultaneously" is forcibly ordered; there is no true parallel writing.
  • Deterministic: All state deductions are deterministic; the same causal input always yields the same state output.

An attack landing in the logic layer is not an animation, but a string of discrete events: attack → hit → damage → loss → die. Each event completes instantaneously, leaving behind a determined state change.

Presentation Layer: The Projection of the Senses

The presentation layer translates the logic layer's discrete changes into continuous audio-visual experiences. Attack animations, chase trajectories, health bar tweens, particle effects—all of these happen here. Its characteristics are the exact opposite of the logic layer:

  • Parallel: Multiple animations can run simultaneously, each doing its own thing.
  • Disposable: A rendering layer crash, skipped animations—none of these affect the facts of the world.

Logic layer events are "what happened"; presentation layer events are "how to perform it."

Where Is the Boundary?

To determine which layer something belongs to, you only need to answer one question:

After this thing ends, have the facts of the world changed?

  • No change → Presentation layer, autonomous (swing animation, camera shake, UI transition)
  • Changed, but only in current scene → Logic layer (HP reduction, gaining Buff, removing enemy)
  • Changed, and cross-scene → Persistent state, must be saved (character level, inventory, quest progress)

Where Did the Continuous Processes Go?

Here there is an obvious question: games contain a huge amount of things that "last for a duration"—a 3-second charge-up, a 0.5-second block window, a combo input period. Isn't the logic layer discrete? Who manages these continuous processes?

The answer is: temporary state windows.

A temporary state window is an asynchronous container within the logic layer. It runs for a sustained duration, listening to time passing and external events, and submits a discrete conclusion to the logic layer when the window ends. For example, a 3-second charge-up: the window opens and runs continuously; when 3 seconds are up, it submits "release skill"; if interrupted midway, the window is destroyed and the conclusion is void.

Temporary states have three properties:

  • Time-bounded: When the window closes, the internal state naturally perishes.
  • Preemptible: When an upper-layer event arrives, the old window can be forcibly cancelled.
  • Sandboxed: The window only produces conclusions, not processes. Process states perish with the window; the logic layer only adjudicates the final conclusion.

This solves a major engineering problem: the logic layer does not completely rule the presentation layer, and does not need to maintain two sets of states at all times. The logic layer still emits discrete serial events outward; it merely has the internal capability to handle concurrent, time-consuming animation processes.

In code engineering, this can be implemented through structured concurrency.

After Separation: Four Agreements

Dividing the world into two layers is only the starting point. The real question is: how can the two separated halves still be the same world?

If there is only separation without agreement, the logic layer becomes a mathematical model in a vacuum, and the presentation layer becomes a showy spectacle detached from facts. The core of Dual-World Theory is not "separation," but "reconnection through agreement after separation."

Input Signals

Player input is continuous—holding a movement key, pushing a joystick. The logic layer can only consume discrete events. The initiative to cut continuous signals lies with the logic layer, not the presentation layer.

The logic layer pre-defines cutting rules: key press is cut into action:start, release is cut into action:end, drag crossing a boundary is cut into target:changed. The presentation layer is responsible for detecting these conditions and reporting discrete events at trigger points.

The presentation layer can autonomously handle continuous inputs outside the rules (camera fine-tuning, hover feedback), but these autonomous behaviors cannot produce semantic signals that players can rely on. If a player sees a monster attacking them and therefore presses dodge, this "attack" must have already been acknowledged by the logic layer—it cannot be a mere feint of the presentation layer.

State Subscription

The presentation layer does not directly read the logic layer's raw state tree. It consumes state through a three-stage process:

  1. Publish: After each state change, the logic layer publishes change records in the form of patches + timeline.
  2. Subscribe: Rendering components declare the state fragments they depend on, receiving only the changes they care about.
  3. Derive: Rendering components can perform visual derivations based on subscribed state (e.g., "calculate health bar color based on HP"), but derivation results are limited to themselves and cannot affect other rendering components.

What the logic layer emits is "what changed in the world"; what the presentation layer decides is "how should I perform this change."

Sync and Discard

The presentation layer's continuous processes are not completely free. The two worlds need to synchronize with each other at specific moments:

  • Align: When the logic layer emits a discrete event, the presentation layer must acknowledge the latest facts of the logic state. For example, when a damage settlement event arrives, the target's true HP is already 87; the health bar may still be tweening from 100 to 87, but if a second damage is issued at this moment, the calculation base must be 87.
  • Transition: Between two alignments, the presentation layer can freely interpolate, predict, and orchestrate animations; the logic layer does not intervene in transitional presentation at all.
  • Discard: If the presentation layer's continuous process has not yet converged and the logic layer has already issued a new event (death animation hasn't finished playing, but the target has already resurrected), the presentation layer needs to directly interrupt the old animation and rapidly transition to the new fact.

At alignment moments, the latest facts must be acknowledged; during transition processes, free play is allowed.

Component Autonomy

Presentation layer autonomy is embodied as a list of limited permissions:

Permission Scope Presentation Layer Autonomy Must Report to Logic Layer
Visual Presentation Animation orchestration, particles, camera push-pull, UI transitions —
Local Feedback Hover effects, press feedback, drag preview On release/confirmation
Spatial Interpolation Chase trajectory, movement smoothing, turn transition On collision trigger/entering range/hit
Behavioral Decision — Attack initiation, skill release, state switch

Core principle: If a player might make a core-state-affecting decision based on this behavior, it cannot be autonomous.

What Does This Philosophy Bring?

Testing-Friendly

In traditional games, causal chains are intertwined with rendering, physics, and engine timing, making independent deduction difficult. Dual-World separates logic from presentation: the same state and event inputs necessarily produce the same outputs, enabling complete causal chain deduction.

Replayability

Traditional state is scattered across object memory and callbacks, requiring extra effort to extract a complete snapshot. In Dual-World, all changes are discrete events; world history is a log. Replay brings you back to any key event.

AI-Friendly

Traditional rules are distributed across animation callbacks and state machines, making them difficult for external systems to read directly. In Dual-World, rules are explicit functions and state is pure data structures—AI can directly understand, predict, and verify.

Conclusion

Dual-World Theory advocates:

Let the deduction of world facts run in the purest, most deterministic way; let sensory experiences run in the freest, most continuous way; then use contracts to ensure that the two are always the same world.

The logic layer handles "what happened"; the presentation layer handles "how to perform it." But the performance is not arbitrary—input signals define which facts that change world state are produced; state subscription defines how facts are consumed; sync and discard define when alignment must occur; the autonomy list defines the boundaries of freedom.

The logic layer is absolutely objective, authoritative, deterministic, and cannot be polluted by presentation; the presentation layer is derivative, interpreted by logical primitives, and has a lifecycle. The two do not know of each other's existence, are orthogonal to each other, cannot call each other, each runs, each lives and dies, and through the same set of agreements they combine into a continuous space-time.
