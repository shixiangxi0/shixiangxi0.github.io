用前端 React 架构写一个杀戮尖塔

组件持有表现，也可以持有行为，但不能持有逻辑。

现代前端中，组件可以独立存在，具有自治性。一个按钮自加 1，它持有视觉表现，也持有触发表现变化的交互行为，但不持有"为什么加 1"的业务逻辑——数据流向哪里、触发什么副作用，不在它的管辖范围。

把这个边界再推一层：组件可以持有行为，但不能持有逻辑。

表现：玩家能看到、听到的一切。

行为：组件自主触发的动作，不改变跨系统的共享状态。

逻辑：影响未来游戏状态的决定性规则。

敌人头上闪出一个红色图标，提示它下回合要攻击——这是行为。图标怎么出现、怎么抖动、持续多久，敌人组件自己处理。但这个图标本身还没有改变任何状态，玩家 HP 没变，手牌没变。真正执行攻击、结算伤害的那一刻，才穿透到逻辑层。

表现层自治

卡牌悬停放大、拖拽轨迹

敌人意图图标闪烁

战斗背景粒子特效

伤害数字飘字动画

上报逻辑层

打出卡牌、消耗能量

敌人攻击结算伤害

抽牌、弃牌、洗牌

施加中毒、虚弱等状态

逻辑层不指挥"播放哪个动画"，它只做一件事：处理上报的事件，计算出新状态，然后下发一份纯数据快照。

{ hp: 45, energy: 1, block: 8, hand: ['打击', '防御'], poison: 3 }

表现层拿到快照，自行决定如何呈现。能量球从 3 颗熄灭到 1 颗、伤害数字飘出来、敌人身体后仰——这些都是表现层的自由。给定同一份快照，表现层必须产出确定性的表现序列，内部的随机和时序都要基于快照参数推导。

这跟 React 的虚拟 DOM 来操作真实 DOM 类似。虚拟 DOM 是轻量状态树，React 比较差异后批量应用到真实 DOM。游戏中，逻辑层下发的快照就是"虚拟状态树"，表现层是"真实渲染管线"。

React
State → Virtual DOM → Diff → Real DOM

Game
Events → Logic Layer → Snapshot → Presentation

对照起来看：React 的状态提升，对应逻辑层集中处理所有状态变更，表现层无状态。单向数据流，对应事件上报到逻辑层、快照下放到表现层，不可反向。纯函数组件 props → UI，对应表现层 snapshot → animation，给定相同输入必得相同输出。Reconciliation，对应表现层对比新旧快照，决定动画过渡策略。合成事件，对应只有改变全局状态的事件才冒泡到逻辑层，局部行为就地消化。

核心差异只有一个：虚拟 DOM 改变的是静态 UI 的变换，快照改变的是连续动画的切换。

这样拆分之后，确定性回放变得简单——只记录事件序列和快照历史，表现层的丰富动画不影响回放一致性。联机对战也简单——逻辑在服务端运行，客户端只接收快照，可本地预测插值。逻辑层是纯数据变换，不依赖渲染管线，可完全无头测试。美术调整动画、特效参数，不触碰逻辑层代码。
