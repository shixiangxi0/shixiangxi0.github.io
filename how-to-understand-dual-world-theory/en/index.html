How to Understand Dual-World Theory

Prerequisite reading: Dual-World Theory: Another Perspective on Game Architecture

Dual-World is not merely a redivision of logic and presentation. More essentially, it is redefining what an "object" should "possess" in this world.

Traditional game objects are usually: Object = Data + Behavior + Presentation

Thus an Enemy:

  • Has HP
  • Has AI
  • Has animations
  • Has special effects
  • Has movement
  • Has hit reactions
  • Has a state machine

Eventually becoming a self-contained universe.

Dual-World Theory holds that: Objects do not possess world facts. Objects only possess behavioral capabilities and presentation capabilities. World facts cannot belong to objects; world facts belong to the logic layer.

This is a form of decentralization brought about at the architectural level.

For example: A character does not "own" its own health. True health exists in the logic layer's state tree, event timeline, and authoritative state. The character object only reads, presents, and reacts to changes.

This makes many things suddenly extremely clear.

For example, why is the "death animation" always so easy to mess up?

Traditional thinking:

Enemy.dead = true
Enemy.playDeath()
Enemy.disableCollision()
Enemy.remove()

Death is simultaneously state, animation, lifecycle, and scene management—all tangled together.

In Dual-World Theory:

logic:
    hp <= 0
    emit die

presentation:
    receive die
    play death performance

scene:
    receive remove_entity
    clean up entity

The causal chain is complete and explicit.

Traditional game development often does not emphasize causality. For example:

Buff modifies AttackSpeed
AttackSpeed affects Animator
Animator changes HitTiming
HitTiming advancing causes ComboWindow change

In the end, no one knows: "Who actually caused what?"

Whereas Dual-World naturally forces developers:

cause → event → state transition → projection

Causality must be made explicit. This is where it is extremely powerful. Because the essence of maintainability is actually causal transparency, or in other words, verifiability and traceability.

Dual-World Theory naturally weakens traditional OOP's "object state-machine centrism"—objects do not possess world facts, and objects cannot hold adjudication power.

Traditional game development easily becomes:

Idle → Run → Attack → Hit → Dead

Then each object has a giant FSM. In Dual-World, state, behavior, time windows, and presentation processes are gradually split into different layers. Eventually the object itself becomes increasingly "thin." What truly becomes thick are event streams, contracts, temporary windows, and behavior combinations.

And "component autonomy" here is not the same as ordinary ECS autonomy. Ordinary ECS autonomy still updates itself every frame. Component autonomy in Dual-World is more like limited-authority autonomy:

Components can run freely and continuously, but cannot tamper with world facts. The entire process must ultimately converge into shareable, adjudicable, replayable world facts.

This is an extremely advanced constraint. It is more like UI's optimistic rendering, or eventual consistency in distributed systems.

This system also has a hidden advantage: it is naturally suitable for multi-person collaboration. Because:

  • Art/Animation only cares about "how to perform"
  • System designers only care about "how facts change"
  • The client only cares about "how to project"
  • The server only cares about "whether causality holds"

Boundaries become exceptionally clear. Many large projects collapse in later stages precisely because: "Everyone is secretly modifying world facts."

There is also something worth mentioning—the macro world never has true parallelism in any meaningful sense. You can understand it as:

The essence of the macro world is not "simultaneity," but "causal relationships are ultimately orderable."

This is crucial. Because the "simultaneity" in our perception—two people swinging swords at the same time, two bullets hitting at the same time, two threads running at the same time—is essentially just inability to distinguish sequence under local observation. But as long as the world needs to produce results, states need to converge, and facts need to hold, the system will ultimately choose a causal order. Otherwise the world cannot be stable.

This is exactly why adjudication is inevitable.

For example, "simultaneous attacks" in a game: two characters simultaneously slash each other to death. It looks like:

A hit B
B hit A

Simultaneous. But the logic layer must answer: who dies first? After death, can skills still trigger? Does lifesteal hold? Does death explosion occur? How is aggro attribution calculated?

Thus the system must order. Even if players feel it is simultaneous, animations are simultaneous, effects are simultaneous—the fact layer must still adjudicate.

Database transactions: two users simultaneously modify balance. In the physical world CPU is parallel, network is parallel, requests are parallel, but the database ultimately serializes. Otherwise money disappears into thin air, state is corrupted, the world distorts.

Thus ACID is essentially: "world facts must be orderable."

Legal system: two people accuse each other. In reality events may happen simultaneously, but the court ultimately forms a narratable causal chain. Because both social order and the media public need a "version of facts." This too is a form of authority, adjudication, serialization.

The term "macro world" is extremely important. Because at the microscopic level, there may indeed exist
quantum superposition,
probability states,
true concurrency,
non-determinism.
But once entering the macro level, the world must converge into narratable reality.

Why? Because macro systems need stable causality.

Otherwise:

Cannot remember
Cannot reason
Cannot collaborate
Cannot predict
Cannot govern

In other words: Civilization itself is built upon the orderability of causality.
